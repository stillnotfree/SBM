> **О разработке:** проект преимущественно создан ИИ-агентом OpenAI Codex под
> руководством человека, с последующим тестированием и проверкой. Независимый
> профессиональный аудит безопасности не проводился.

Если функция прямо не указана в примечаниях к релизу, этот README описывает
текущее дерево исходного кода и не утверждает её наличие в релизе v1.1.11.

## Возможности

- Нативное приложение на Swift в строке меню, TUN-режим без Electron.
- Режимы Rule, Global и Direct, автоматический или ручной выбор сервера.
- Несколько HTTPS-подписок и ссылок VLESS/Hysteria2/Shadowsocks в одном профиле.
- Разделение серверов по источникам с сохранением порядка подписки, отображением пинга и exclude regex.
- Отдельные User-Agent, X-App-Version, X-Device-OS и X-HWID для каждой подписки.
- Маршрутизация выбранного приложения напрямую, через текущий proxy, стабильный сервер или REJECT.
- Локальный Routing Inspector без сетевых и process-проб.
- JSON-конфиги sing-box для остальных поддерживаемых ядром протоколов.
- Ограниченный редактированный support snapshot в виде текста или versioned JSON.
- Без system proxy, веб-панели, статистики трафика, телеметрии и access-логов.

## Установка

1. Скачайте последнюю DMG для Apple Silicon в
   [GitHub Releases](https://github.com/stillnotfree/SBM/releases/latest).
2. Откройте DMG и перенесите **SBM.app** в Applications.
3. Если Gatekeeper заблокирует запуск, выберите **System Settings > Privacy &
   Security > Open Anyway**.
4. Откройте **Settings…** и добавьте подписку, ссылку подключения или JSON-профиль
   sing-box.

SBM запускается при входе в macOS и автоматически подключает выбранный
сохранённый профиль.

## Источники профилей

В одном управляемом профиле можно объединить:

- несколько компактных HTTPS-подписок;
- несколько ссылок `vless://`, `hysteria2://`, `hy2://` и `ss://`.

Для каждой HTTPS-подписки отдельно настраиваются `User-Agent`, `X-App-Version`,
`X-Device-OS` и `X-HWID`. Новые источники воспроизводят стабильные поля из
пользовательского capture запроса Happ 5.4.0 для iOS. SBM не выдумывает модель
iPhone, версию iOS, locale и транспортные headers конкретного устройства. При
переходе на другой origin
секретные заголовки удаляются. Точные дубликаты подключений объединяются,
максимум — 63 подключения в профиле.
Сброс preset заголовков не меняет HWID источника. Копирование и явная
регенерация HWID доступны отдельно. Новые значения имеют канонический формат UUID; SBM не утверждает, что повторяет
внутренний алгоритм Happ. При обновлении подписки или приложения HWID не ротируется.

Управляемые подключения используют типизированные стабильные ID. Библиотека
профилей в формате v1.1.11 (схема 1) автоматически мигрирует через отдельную
границу DTO; предыдущая текущая схема 4 также переписывается в текущую схему 5
до использования. При обновлении подписки узел, который
только переименован или переставлен и не изменил идентичность подключения,
сохраняет ID; активный управляемый профиль для одного такого изменения не
активируется повторно. Изменившийся outbound или политика маршрутизации
проверяются и сохраняются как желаемое состояние, пока известный хороший
runtime продолжает работать; **Reconnect to Apply** выполняет необходимую
явную остановку и последующий запуск.

Компактные ссылки Shadowsocks ограничены URI `ss://` строгого SIP002 без
плагинов. Поддерживаются ровно методы `aes-128-gcm`, `aes-256-gcm`,
`chacha20-ietf-poly1305`, `2022-blake3-aes-128-gcm`,
`2022-blake3-aes-256-gcm` и `2022-blake3-chacha20-poly1305`. Плагины, любые
query-параметры и устаревшая форма с Base64 для всего URI отклоняются. Эта
поддержка компактных ссылок не означает поддержку произвольных конфигураций
Shadowsocks или других протоколов: используйте отдельный нативный JSON-профиль
sing-box, когда нужную конфигурацию допускают bundled core и политика импорта
SBM.

Для каждого источника доступен необязательный `Exclude regex`. Совпавшие с ним
имена подключений не попадают в меню, Auto и итоговый конфиг sing-box. Например,
`(?i)lte|russia` скрывает имена с `LTE` или `Russia` без учёта регистра. Источники и серверы сохраняют порядок из профиля/подписки; измеренный пинг
показывается как метаданные и не переставляет пункты ручного выбора.

Отдельными профилями поддерживаются:

- локальный JSON-профиль sing-box;
- JSON-профиль sing-box по HTTPS.

Полный JSON-профиль намеренно не смешивается с компактными источниками.

## Цель измерения задержки и приватность

В **Settings… > Advanced** задайте HTTPS-цель в поле **Test target** и выберите **Apply**,
чтобы сохранить её. SBM принимает только абсолютный HTTPS URL без учётных
данных и фрагмента. Пока VPN подключён, проверка задержки отправляет HTTPS
запрос к этой цели через каждый проверяемый прокси; выбирайте endpoint,
которому доверяете. Его оператор видит время запроса и egress-адрес прокси,
как при любом HTTPS-запросе к этому endpoint. Цель измерения задержки отделена
от URLTest-интервала sing-box, используемого для выбора Auto. Ручные тесты
сразу используют новую применённую цель; созданные SBM группы Auto получают её
при следующем обычном подключении. Импортированные native URLTest не меняются.

Постоянно доступное окно Diagnostics копирует ограниченный support snapshot как текст или JSON с
отсортированными ключами. Он агрегирует только уже известное приложению
состояние и не запускает DNS-, network-, latency- или process-пробы. Имена и ID
профилей/узлов, данные подписок, headers, credentials, raw native JSON и логи не
включаются. Recent Errors хранит не более 50 предварительно очищенных ошибок,
дедуплицирует соседние повторы и повторно очищает данные при экспорте. Большая
история детерминированно обрезается, не удаляя текущий статус целиком.

Команда **Refresh** обновляет наблюдаемый статус и один раз принудительно
синхронизирует каждый удалённый источник подписки, не перезапуская VPN.
Повторный полный sweep объединяется с уже выполняющимся, а изменение активного
профиля сначала проверяется, но изменённые байты не заменяют работающий
известный хороший runtime автоматически: для применения используется
**Reconnect to Apply**, который явно останавливает и запускает последний
сохранённый candidate. Удалённый или изменённый до своей очереди источник не
запрашивается со старым URL или headers. При ошибке активации корректно
обновлённые данные остаются сохранёнными для повтора, а новые routing-правки не
откатываются старым snapshot. Закреплённый sing-box
1.13.19 не предоставляет поддерживаемой ограниченной команды принудительного
обновления rule-set работающего core; они продолжают следовать
`update_interval`.

К управляемым подпискам и ссылкам можно добавить собственный JSON с
маршрутизацией. Пример
[`Examples/routing-ru-direct.json`](Examples/routing-ru-direct.json) направляет
российские домены и IP-диапазоны напрямую, оставляя остальной трафик через VPN.
Списки загружаются из официального репозитория SagerNet и обновляются ядром.

Website Routing хранит до 128 нормализованных доменов на профиль и направляет
апекс вместе с поддоменами в Proxy, Direct или Reject. Порядок: обязательные
safety-правила, Website Routing, Application Routing, импортированные правила,
финальный маршрут. Функция одинакова для compatibility и native профилей.

Правило приложения использует точный main executable выбранного `.app`. Оно
выполняется после Website Routing и до импортированной
маршрутизации. Цель REJECT использует нативное действие sing-box и блокирует
сетевые соединения выбранного приложения. Перемещённое или удалённое приложение остаётся в списке, но
правило неактивно; SBM не угадывает процесс по имени и не сканирует bundle.
Отдельной DNS-политики для приложения нет.

Routing Inspector объясняет детерминированный итог для домена или IP по
собранному route. Он не делает DNS-, network-, process- или persistence-проб.
`Default traffic` означает трафик, который не совпадает ни с
одним настроенным правилом приложения; выбранное приложение проверяется по его
точному сохранённому executable path. Основной результат — PROXY, DIRECT или
REJECT. Для remote rule-set helper читает точный активный кэш sing-box и
вызывает ограниченную команду `rule-set match` закреплённого core; Explain не
скачивает списки, а через IPC возвращаются только результаты совпадения. Если
профиль неактивен, кэш отсутствует или правилу нужны resolved IP, port,
protocol либо иной process context, Inspector отдельно указывает ограничение.

Нативные JSON-профили сохраняют собственные outbounds, DNS, правила
маршрутизации и удалённые rule-set. Если в профиле нет selector или URLTest,
приложение создаёт локальные группы выбора сервера и Auto.

Полный candidate, включая новый API secret, обязательно проходит `sing-box
check` до применения. Изменённый candidate не останавливает работающий
известный хороший runtime: он сохраняется как желаемый до явного reconnect, а
helper сохраняет этот факт в durable state, чтобы после перезапуска статус не
выглядел ошибочно активным. После успешного **Reconnect to Apply** и
подтверждённого authoritative status маркер очищается. Ошибка остановки не
запускает candidate; ошибка запуска после остановки оставляет VPN отключённым
и действие доступным, без автоматического цикла повторов. Это не seamless
handoff и не гарантия системного kill-switch для обычного TUN.
В режиме Rule импортированный `route.final` заменяется управляемым из меню
селектором: весь не совпавший с правилами трафик идёт через выбранный в SBM
сервер. Сгенерированный TUN имеет IPv4/IPv6-адреса, `auto_route` и
`strict_route`; literal IPv6 следует тому же Proxy/Direct/Reject маршруту.
Реальная проверка route table и отсутствия физического bypass описана в
`docs/manual-validation.md` и не доказывается только config-тестами.

Привилегированный helper принимает команды только от локальных учётных записей
администраторов. Он проверяет и ограничивает импортированные профили перед
запуском корневого процесса sing-box, поэтому все локальные администраторы
macOS входят в доверенную границу приложения.

## Требования

- Mac с Apple Silicon;
- macOS 26 или новее;
- права администратора для установки фонового helper.

## Разрешение фонового helper

Приложению нужен привилегированный helper для управления TUN-интерфейсом.
Ad-hoc подпись может потребовать открыть **System Settings > General > Login
Items & Extensions** и разрешить `SBMHelper`. SBM дождётся системного статуса
разрешения, а затем автоматически проверит или заменит helper; отдельные
действия Refresh или Repair после возвращения в SBM не требуются.

Обычный выход, включая **Disconnect & Quit** и Command-Q, сначала отключает VPN
и останавливает ядро. Если остановка не подтверждена, приложение отменяет
завершение и остаётся открытым для повторной попытки.
Недоступный helper отображается как неизвестное состояние VPN, а не как
подтверждённое отключение. Явный Disconnect остаётся приоритетным при дальнейших
изменениях настроек и подавляет автоматическое переподключение в текущей сессии.

## Профили и приватность

Профили и учётные данные хранятся в
`~/Library/Application Support/SBM/profiles.json` с правами `0600`. Это устраняет
запросы Keychain, но не защищает данные от другого вредоносного ПО, уже
работающего от имени того же пользователя macOS.

Локальный SOCKS5, если включён, слушает только `127.0.0.1`. Управляющий API также
доступен только через loopback. Приложение не ведёт access-логи и ограничивает
размер warning-лога.

## Обновления

SBM проверяет GitHub Releases не чаще одного раза в сутки или вручную. Загрузка
принимается только по HTTPS, только для точного Apple Silicon DMG и только при
совпадении SHA-256 digest, опубликованного GitHub. Установка остаётся ручной:
проверенная DMG открывается, после чего пользователь заменяет приложение.

## Сборка

```sh
make dmg
```

Перед упаковкой предполагаемого релиза запустите локальную непубликующую
проверку с версией, уже указанной в metadata репозитория, например:

```sh
make release-check TAG=v1.1.13
```

Она проверяет metadata релиза и локальные команды верификации, затем собирает и
проверяет `dist/SBM.app`. Команда не создаёт tag или release, не делает commit,
push, install и не открывает SBM.

Версия sing-box фиксируется в `Core.lock`. Обновление выполняется явно командой
`scripts/update-core.swift stable`: prerelease-версии отклоняются, а официальный
архив, исходный бинарник, подписанный bundled core и встроенный в helper digest
проверяются отдельно.

Для воспроизводимого локального baseline CPU, памяти и wakeup используйте
[протокол baseline производительности](docs/PERFORMANCE.md). Его read-only
sampler получает PID от пользователя и выводит JSON Lines; результат относится
только к указанным машине, сборке, профилю, сети и процедуре, а не является
общим утверждением о производительности или энергопотреблении SBM.

Готовая DMG появляется в `dist/`.

## Статус

Версия 1.1.13 включает зафиксированное стабильное ядро sing-box 1.13.19 и не
является независимо аудированным продуктом безопасности.
Мульти-подписки, пользовательские заголовки, VLESS + REALITY + Vision и
Hysteria2 + TLS покрыты тестами, однако это не означает проверку каждого
протокола sing-box с каждым провайдером.

О предполагаемых уязвимостях сообщайте через
[закрытый канал GitHub](SECURITY.md), а не в публичном issue.
